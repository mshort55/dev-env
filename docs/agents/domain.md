# Domain docs

Read the root `GLOSSARY.md` before exploring the repo. Read any architecture
decision records (ADRs) in `docs/adr/` that apply to the work. If a file or
directory is absent, continue.

Use glossary terms in issues, proposals, tests, and code. When a term needs
a definition or a decision needs a record, use `/domain-modeling`.

If a proposal conflicts with an ADR, identify the record and explain why
the decision warrants reconsideration.
